# ZYG-ZXG design direction

Identity: a dark, mysterious **pixel-art** synthesizer. Serum 2 users should feel at home, so every module sits where it does in Serum 2, but the look is entirely our own: void-violet chassis, acid-green "live" accents, evil-purple selection/routing accents, amber/crimson for warp, drive and warnings. The palette and metrics come from `ui-design-kit/design-tokens.json`; the logo is the ZYG-ZXG eye-and-wings mark. Serum artwork, skins and code are never copied.

## Rendering rules
- Everything is drawn on whole pixels with no anti-aliasing: two custom bitmap faces, ~35 icons and procedural knobs (`src/ui/PixelGfx.*`). Nothing depends on system fonts. Type scale: the regular face is a condensed 7px cap height (most glyphs 4px wide, so it has the old 5px face's advance and layouts keep their widths) for labels, values and headers; the 5px `small` face (`drawSmall`, `small=true`) is only for secondary marks — axis ticks, frame counters, hints, badges. Bold (double-struck) is reserved for module/section titles.
- The window is freely resizable (minimum 1000x600) and always opens at 1280x720 x UI scale; only the scale (and the GPU toggle) persist in `~/.config/ZYG-ZXG/ui.txt`. The layout is fluid on a logical canvas of `window size / UI scale`; UI scale is an integer (100/200/300%) so pixels stay square.
- Vertical proportions follow Serum 2: after the 52px top bar and 68px keyboard dock, the page gets 54% of the remaining height and the modulation section the rest (floors 290/208). OSC-page modules share one vertical rhythm (`OscPage.cpp`: header, two selector rows, display band, footer row, two 50px knob rows) so knob rows line up across SUB/OSC/NOISE/FILTER. Column shares at 1280: SUB ~6.5%, each OSC ~22%, NOISE ~8%, FILTER the rest; the SUB shape grid fills the display band with near-square cells.
- Displays are procedural and redraw at 30 Hz (idling at ~4 Hz when static): the wavetable is a 3D mesh (x = sample, depth = frame, height = amplitude; real frames when >= 3, a 12-slice crossfade for 2-frame tables) rasterised into a cached image and rebuilt only when table/warp/size change; the current frame is drawn live on top with both warp slots applied in engine order (PM/RM/AM previewed with the source oscillator at equal pitch, FM shown unwarped) and follows the engine's modulated WT position/warp amounts while a voice sounds. The filter display overlays a 4096-point Hann FFT of the plugin output (peak per log-frequency column, +4.5 dB/oct tilt, fast attack/38 dB/s fall) on the response curve.
- Rendering: the editor attaches a JUCE `OpenGLContext` (component painting on the GPU) by default; MENU -> GPU RENDERING toggles it and `ZYGZXG_NO_GPU=1` forces software. Snapshots (`zygzxg_ui_snapshot`) always use the software renderer.
- Layout follows Serum 2: top bar (logo, OSC/MIX/FX/MATRIX/GLOBAL, preset field, browser/menu/undo, master), page area, macros + ENV/LFO/VELO/NOTE section, keyboard dock.

## Honesty rules (unchanged)
Imported settings stay inspectable and editable. The top bar shows `SERUM IMPORT <version>` versus `ZYG NATIVE` and a diagnostics count (missing assets, preserved-but-not-rendered state). A parsed field is never shown as an active feature unless native behaviour exists; displays that approximate DSP (filter response, envelope playhead) draw from the real parameters, and per-source meters are omitted because the engine does not expose them.

## Motion
Animation is used to explain state, never to decorate: eased hover/press/LED/tab transitions (`src/ui/Anim.h`), page and preset-change entrances, toasts with a spinner while loading, modal fade+slide, and live displays that react to played notes and output level (filter spark, wavetable scan, envelope/LFO playheads, reverb tail and rings, delay taps, distortion operating point, compressor level dot, modulation sweeps).

## Information architecture
OSC (SUB, A/B/C, NOISE, two filters) - MIX (routing strips, buses, main, direct) - FX (Main/Bus 1/Bus 2 rack with splitter bands, add/remove/reorder/bypass) - MATRIX (editable route table) - GLOBAL (tuning, portamento, voicing, quality/MPE, time scale, voice panel, interface) - bottom section (macros, four envelopes, ten LFOs with drawable curves, velocity/note, voicing) - modal preset/wavetable/sample/impulse browser, CLIP and ARP editors, diagnostics.

## Modulation, FX rack and presets (2026-09-27)
- Every continuous control that maps to a `TargetId` is a modulation destination through `ModDest`: drop a source handle on it (ENV/LFO tabs, VELO/NOTE, macro handles, MW/PB/AT chips in the dock) or right-click > MOD SOURCE. Knobs show violet arcs, spinners a violet range bar under the field, faders a violet column beside the groove. Right-click no longer resets silently; alt/ctrl-click (knob) or alt-click (spinner/fader) resets.
- FX modules identify themselves with a 48x30 procedural glyph in the effect colour (delay pulses, reverb tail, IR ring, clipped sine, detuned sines, comb teeth, wide notches, EQ bells, resonant LP, knee curve, shifted wave, stacked saws, gain staircase, forks, ducking fins, stutter slices). Names remain in the rack list and menus.
- Preset browser layout: search + source/format chips on top, type list left, NAME/TYPE/LOCATION/FORMAT list, footer with OPEN USER FOLDER and DONE. It never closes on a single click.

## Retro hardware screens (2026-09-27)
- Every display is rendered as late-1990s hardware: green LCD (oscillators, noise, envelope; visible pixel grid, slow LCD response) or violet CRT (filter/spectrum, LFO, velocity/note map; scanlines, phosphor decay, stronger bloom); FX scopes are CRTs in their effect colour. Content code is unchanged and draws into a canvas; `RetroScreen::present` does the hardware look. Colour depth is limited to two phosphors + white at 6 levels with ordered dither, so gradients band/dither like real screens. Labels inside screens stay crisp (captured and replayed with a faint halo). Controls, labels, proportions and the purple/green identity outside the screens are unchanged.
