# Preset and asset formats

## Serum 2 `.SerumPreset`

Publicly documented by [serum-preset-packager](https://github.com/KennethWussmann/serum-preset-packager) and independently verified against the supplied user preset and 626 factory presets. Container layout, little-endian:

```text
offset  size  meaning
0       9    ASCII "XferJson" plus NUL
9       4    metadata JSON byte length
13      4    metadata flags (0 in examined presets; preserved if unknown)
17      N    UTF-8 metadata JSON
17+N    4    uncompressed CBOR byte length
21+N    4    payload flags (2 in examined presets)
25+N    ...  Zstandard-compressed CBOR state
```

`zygzxg/serum.py` and the native C++ `SerumImporter` bound file and decompressed size and return the full CBOR object. The Python `encode_bytes` reserializes all decoded fields, including unknowns, for research tests. The C++ importer maps a first subset into a typed `Patch` while keeping the entire source state in a provenance sidecar. JSON/CBOR map ordering and Zstandard bytes may differ after re-encoding. Legacy `.fxp` is separate and unsupported.

The state tree has named objects such as `Oscillator0..4`, `VoiceFilter0..1`, `RoutingSlot0..6`, `Env0..3`, `LFO0..9`, `Macro0..7`, `ModSlot0..63`, `FXRack0..2`, `ArpClip0..11`, `MidiClip0..11`, `Global0`, `VoicePanel0`, and `PitchQuantizer0`. Subobjects and defaults are mode dependent. Many explicit controls are under `plainParams`; other semantic state such as curve points, clip events, SFZ text, source IDs and asset paths lives elsewhere. A literal string `"default"` is used in parts of the tree. Never infer a zero or “off” control from an absent key without a verified default table for the exact Serum version.

The [factory corpus schema](SERUM2_CORPUS_SCHEMA.json) is generated by `scan-corpus` and lists observed explicit parameter paths and enum values. It omits an exhaustive schema for non-`plainParams` nested data and is not a complete parameter registry. Study the official manual alongside isolated fixtures for units, ranges, scales, and defaults.

## Independent ZYG patch model and native format

A versioned `.zygpreset` document should encode synthesis concepts independently of Serum names: source modules with mode-specific state; audio-rate routing graph; modulation graph/ordered routes; envelopes/LFOs/macros; voice/global settings; arp and MIDI clips; ordered FX racks and splitter branches; logical asset references; metadata; and an `ImportedFrom` provenance record. Preserve unknown Serum fields in a tagged opaque sidecar with original module path, raw value, import version and diagnostic status. The sidecar should survive ZYG save/reload, but it must not count as semantic support.

Avoid storing absolute machine paths inside a portable patch. Store category and relative reference plus optional content hash; resolve against configured local libraries. Store imported source identity/provenance without embedding copyrighted factory content. Host state should serialize the complete patch and required user-edit state deterministically.

The C++ typed patch model is now implemented in first-slice form: oscillator modes/assets/pitch/unison/warp shell, filters, routes, envelopes, ordered modulation routes, FX module shells, arp/MIDI clip state, macro/LFO state, voice/global fields, diagnostics and source provenance. Much of it is **not yet rendered**. A portable native `.zygpreset` file format is **not implemented**. The VST3 host state currently stores the original Serum preset bytes plus the local asset-root path, then re-imports on restore; this is a migration step, not the final native preset format. Do not add direct `Serum parameter ID → DSP knob` dependencies to `SynthEngine`.

## Local factory-content index

The supplied 2.1.5 installer was listed and extracted with `7z`, without executing the EXE, into Git-ignored `.local-serum-content/`. The indexer records relative paths and sizes under recognized content folders and stores an absolute source root in the local index. It never copies the assets into ZYG. An extracted or installed content folder with `Tables/`, `Samples/`, `Multisamples/`, etc. can be indexed with:

```sh
PYTHONPATH=. .venv/bin/python -m zygzxg.cli index-assets /path/to/Serum-2-Presets --output /path/to/private/zygzxg-index.json
```

`resolve-asset` matches exact category-relative paths case insensitively and reports `resolved`, `missing`, or `ambiguous`. It recognizes Serum's category-root slash, relative sibling-folder paths, and selected Windows authoring paths rebased to a known content-root suffix. Path normalization cannot escape the indexed content root. The current inspector recognizes wavetable, noise, sample/granular/spectral audio, SFZ, multisample child files and convolution IR references. When a multisample has embedded SFZ text, the external SFZ file is not required but its child audio is. It does not yet search multiple configured roots, inspect embedded audio payloads, hash/validate media, or resolve every user-library convention.

To extract from the NSIS installer using an external `7z`, select only the content folders and keep the output private. The updater is an EXE that `7z` did not recognize as an archive; it has not been run. Do not ship extracted content, the original installer, or an index of proprietary asset paths in a ZYG release.
